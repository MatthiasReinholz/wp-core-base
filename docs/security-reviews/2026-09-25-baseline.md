# v1.6.0 baseline security review

Reviewed on 25 September 2026 against PR 103 source commit `81cb9ce12973278c5143b3f9337dbf079285d5f7`: WordPress 7.1.2, WooCommerce 11.1.2 and Jetpack 16.2. Subsequent review-document changes do not modify those runtime files. This is a disposition record for specific findings, not certification of the entire upstream runtime.

The completed CodeQL analysis exposed 54 open alerts on the proposed branch. Review covered their exact locations and relevant callers. Three genuine upstream issues remain open. Separate manual review also identified an inherited upstream editor-content handling concern; its detailed evidence and proposed private handoff are retained outside the public repository pending upstream assessment. No upstream report has been sent by the audit automation.

Dispositions are limited to the reviewed source and call chains. No rule was globally disabled and no path exclusion was added. An isolated browser harness encountered an unrelated module-load error in its broader paste checks; it is not accepted as evidence that the complete editor paste path is safe. The independent source review retains that concern.

## Open upstream engineering work

- **P1: Complete private review and remediation of the inherited editor-content handling concern.** The same relevant source pattern exists in the prior WordPress 6.9.9 baseline. A baseline rollback alone is not a mitigation. Do not represent the runtime as security-cleared; downstream browser-content workflows require separate acceptance. Detailed reproduction material is intentionally omitted here.
- **P2: Correct the featured-image editor fallback's excessive regular-expression backtracking ([alert 230](https://github.com/MatthiasReinholz/wp-core-base/security/code-scanning/230)).** Bounded tests confirmed the problem; the expression is unchanged from the prior baseline. The affected path is the editor fallback for deriving a featured image from post content. The frontend PHP renderer uses a different implementation.
- **P3: Correct source-map trailer matching in the module loader ([alert 231](https://github.com/MatthiasReinholz/wp-core-base/security/code-scanning/231)).** Excessive backtracking was reproduced, but input is already trusted executable module source. No additional unauthenticated input boundary was established.
- **P3: Replace manual JavaScript URL-string quoting with complete string serialization ([alert 242](https://github.com/MatthiasReinholz/wp-core-base/security/code-scanning/242)).** The helper is incomplete for arbitrary raw strings. Current inputs are canonical response URLs, generated blob URLs or trusted import-map identifiers; exploitation through those callers was not established.
- **P3: Match embed providers by parsed hostname.** Current presentation classifiers can misidentify provider-looking paths or query strings. This is a correctness improvement, independent of the scanner's alleged URL authorization boundary.

Source-level upstream proposals and bounded semantic/performance checks were prepared for the regular-expression and string-encoding changes. They are proposals for upstream review, not modifications to official WordPress files or claims that every possible input has been tested. No upstream patch has been released as part of this framework version.

## Release scope

The signed framework ZIP excludes WordPress runtime code, plugins and themes. Adopting it through `framework-sync` does not replace downstream runtime dependencies. The tagged optional starter includes official WordPress runtime files and therefore retains the open upstream findings described above. Framework publication is not a blanket runtime security clearance.

Core and plugins retain their official managed-source integrity. Silently patching generated bundles would break that provenance and be overwritten by later managed updates. A supported upstream fix or an independently reviewed, explicitly owned containment is required before any corresponding runtime issue can be marked fixed.

The coordinated baseline upgrades include seeded migration and paired database/runtime rollback checks. Those checks establish the documented store invariants across the supported CI matrix; they do not establish browser-security coverage, production-store compatibility or absence of all vulnerabilities. See [baseline upgrades](../baseline-upgrades.md) for the downstream rehearsal procedure.
