# WordPress 7.1.3 baseline security review

Reviewed on 8 October 2026 against the managed update candidate
`36c7046f8bd8d40b860eaf799827a1e7ffb7417d` (upstream PR #112), carried into
PR #115. This renews the specific inherited-finding review for WordPress 7.1.3;
it does not certify the entire runtime or declare those findings fixed.

## Source and change review

All 15 changed WordPress runtime files were independently compared byte-for-byte
with the official Linux/AMD64 WordPress 7.1.3 image
`wordpress@sha256:8a93deeb4c1c110cbd9e8a0fd4bfde32b212d9f55d910962277c87f31b252e11`.
They match. The managed updater also reported official checksum verification.
No local modifications to upstream runtime files are introduced.

The reviewed changes include integer normalization of export query IDs; a bound
on relative-URL path normalization when no replacement occurs; stricter sticky
post capability checks; post visibility checks before singular comment-feed
queries; validation of registered post statuses/types before dynamic status
hooks; and DOM-only help-panel selection. Other changes remove obsolete oEmbed
providers, guard image metadata parsing when DOM is unavailable, and update
admin presentation and release metadata. These changes do not replace the
inherited editor and module-loader sources covered by the prior review.

## Inherited findings retained

All 14 source SHA-256 entries in `.github/security-review.json` remain unchanged
and were verified against the candidate files. The exact registered scanner
locations, rule IDs, categories and source-path sets are unchanged. The three
open scanner findings (230, 231 and 242) and the separate manual editor-content
concern therefore retain their existing dispositions and limitations from the
[25 September review](2026-09-25-baseline.md). None is newly suppressed,
closed, or claimed remediated by this patch release.

The register now points to this renewal so it is included in the immutable
release-review inputs. The previous review remains an unchanged historical
record. Renewing the version field does not bypass source hashes or the scanner
inventory contract.

## Release and deployment boundaries

Offline source-review validation establishes the reviewed baseline only. Fresh,
successful CodeQL analyses and the complete matching open-alert inventory for
the exact merged commit remain mandatory before framework publication. This
review does not claim that those future scanner checks have already completed.
The policy still reports `reviewed_with_open_findings` and
`runtime_security_cleared: false`.

The signed framework ZIP excludes WordPress runtime code. The optional starter
includes this reviewed baseline and retains its inherited findings. Production
WordPress uses a separately promoted image; merging this framework change does
not update that image or its database. Existing database-backed upgrade and
rollback fixtures, and downstream backup/schema verification, remain required.
