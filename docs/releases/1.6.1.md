# wp-core-base 1.6.1

## Summary

Closed automation PRs now receive independent branch-cleanup jobs. Previously, several PRs closing close together could replace a pending reconciliation run in GitHub's shared concurrency group, leaving its managed branch behind even with `cancel-in-progress: false`.

Reconciliation still serializes dependency synchronization with scheduled updates. The automation doctor now checks the separate cleanup and synchronization groups, and regression coverage rejects configurations that can discard close events or interrupt active mutations.

## Downstream Impact

This patch updates GitHub automation and its validation. Trusted default-branch checkout, closed-PR metadata checks and revision-checked branch deletion remain in force. GitLab pipelines and runtime dependency versions are unchanged.

## Migration Notes

No runtime or database migration is required. Existing cancelled cleanup runs require explicit recovery; upgrading the workflow does not replay past events. Follow the managed-branch cleanup recovery instructions in [operations](../operations.md#blocked-prs).

## Downstream Workflow Changes

The managed `wporg-updates-reconcile.yml` workflow moves concurrency from the workflow level into its two jobs. Cleanup uses a group containing the PR number; only `sync` uses `wp-core-base-dependency-sync`. The downstream template and example follow the same contract. Permissions and triggers are unchanged.

## Required Downstream Actions

Adopt the signed framework update and review the workflow diff. Run `framework-sync --check-only --fail-on-skipped-managed-files` before rollout when customized managed files must block the update. If a customized reconciliation workflow is skipped, apply the job-level concurrency separation manually and remove its shared workflow-level group. Run `doctor --automation` with the configured automation credentials after the update.

For missed historical cleanup, recover each affected closed PR individually using the documented procedure. A healthy open-PR update report does not establish that every closed-PR cleanup completed.
