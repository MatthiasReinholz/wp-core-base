# wp-core-base 1.6.5

## Summary

This patch restores two older-client compatibility cases found during upgrade review: custom provider timestamps using compact offsets or reduced precision, and existing PR metadata containing a comment terminator inside a JSON string. It also makes historical installer compatibility a required maintainer CI check and consolidates downstream migration instructions.

## Downstream Impact

Custom providers may continue returning PHP `DateTime::ISO8601` timestamps with compact numeric offsets, minute-precision timestamps, and basic date/time forms with an explicit timezone. Calendar, time and numeric offset validation remains strict; natural-language and timezone-free values remain rejected.

PRs generated before v1.6.4 remain recognizable when a valid metadata JSON string contains literal `-->` text. The reader locates the final block's closing delimiter outside JSON strings while preserving the final-marker authority and malformed-final rejection introduced in v1.6.4. Branch identity guards remain unchanged.

## Migration Notes

No new manifest or runtime migration is required for this patch. Existing valid metadata and provider values retain their decoded values. If v1.6.4 left an older metadata-bearing PR unrecognized, adopt this correction before rerunning its updater.

When upgrading across older releases, follow [the consolidated framework upgrade guide](../migration-guide.md#upgrading-an-existing-framework-installation). It covers the v1.4.8 executable-mode repair, v1.5 configuration and CLI validation, customized v1.6.1 reconciliation workflows, and review of conflicting PR metadata. A framework update does not update a site's core, plugins or database.

## Downstream Workflow Changes

No framework-managed downstream workflow or pipeline template changes are included. Maintainer PHP 8.4 CI now verifies the exact published v1.4.8 artifact and its official signature before exercising the historical installer across both profiles and both hosts. A failed download or verification blocks the job. The verified-input receipt is retained with the test report.

## Required Downstream Actions

Adopt the signed framework update, review its diff, and run normal downstream validation. Preflight with `framework-sync --check-only --fail-on-skipped-managed-files --json` when customized managed files must block rollout. Reconcile skipped files manually, then run `doctor --automation` and `stage-runtime` for your profile. Rehearse custom premium provider resolution before rollout.
