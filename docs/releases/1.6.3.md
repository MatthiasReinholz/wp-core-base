# wp-core-base 1.6.3

## Summary

This patch release resolves issue #76: support-forum crawling could keep update jobs occupied for long periods without visible progress. Advisory forum scans now have bounded per-plugin budgets, visible progress, and explicit incomplete-coverage reporting while healthy dependency updates continue.

## Downstream Impact

Defaults limit a plugin's support enrichment to 10 listing pages, 100 HTTP requests, 75 topic-detail requests and 30 seconds of active scanning across its queued PR versions. Each request is bounded by the remaining allowance, uses one attempt and follows no redirects. RSS remains the fast path when it covers the release window.

Incomplete scans preserve previously observed topics and support labels. They retain the last verified incremental watermark; new or retargeted releases without complete coverage keep their full release window pending. Successful scans use a one-second overlap at scan start to avoid missing topics at timestamp boundaries. Malformed or unavailable forum data cannot establish complete coverage.

## Migration Notes

Existing manifests require no changes. Optional `automation.support_forum` settings and `WP_CORE_BASE_SUPPORT_FORUM_*` overrides configure the documented limits. Overrides affect only the current process and are not persisted. See [manifest limits](../manifest-reference.md#support-forum-limits) and [operating guidance](../operations.md#bounded-support-forum-scanning).

The sync report adds `advisory_warnings` and `advisory_warning_count`. Its existing source-warning fields, status and exit behavior remain compatible. Progress goes to stderr, leaving machine-readable stdout intact. `WP_CORE_BASE_JSON_LOGS=1` retains structured logging.

## Downstream Workflow Changes

No framework-managed workflow or pipeline template changes are required. The existing report-summary command displays support advisories. Advisory-only runs remain successful under `--fail-on-source-errors`; real dependency-source failures still return exit code 3 under that option and retain normal source-failure issue handling.

## Required Downstream Actions

Adopt v1.6.3 through `framework-sync` or the signed framework snapshot, then run normal downstream validation. High-volume forums may remain advisory when their historical release window exceeds the configured budget. Review those forums manually when needed; incomplete coverage is not evidence of absent regressions.

## Operational Notes

Official WordPress and plugin runtime files are unchanged. The signed asset contains framework tooling and documentation only. This release does not alter the inherited runtime findings recorded in the [baseline review](../security-reviews/2026-09-25-baseline.md).

The authoritative assets remain `wp-core-base-vendor-snapshot.zip`, its checksum and detached signature. Publication requires the merged release revision's CI and fresh security review. Support coverage remains separate from archive authenticity and dependency-source health.
