# wp-core-base 1.7.1

## Summary

This release updates the optional starter baseline to official Jetpack 16.3.1
and Contact Form 7 6.2.2, and refreshes the reviewed `shivammathur/setup-php`
commit pin in generated GitHub workflows to 2.40.0. Managed runtime files retain
their verified upstream bytes after the existing sanitation policy; no
third-party source patch is added. Published release notes, tags and signed
artifacts for earlier versions remain unchanged.

## Downstream Impact

Jetpack 16.3.1 restores scrolling on the standalone Forms single-response page;
its other changes are package version metadata. Contact Form 7 6.2.2 validates
form submissions against unslashed request data instead of WordPress's
magic-quoted `$_POST`, so values containing quotes or backslashes are no longer
validated in escaped form. Plugin runtime requirements are unchanged from
v1.7.0: the optional starter still requires WordPress 7.1 and PHP 8.3 or newer.

Generated GitHub workflows use `shivammathur/setup-php` 2.40.0, pinned to commit
`eb7c497e18156a6bbabfef1d3a82760b9eda3962`. No inputs, permissions, jobs or
GitLab pipeline behavior change.

## Migration Notes

Framework sync updates tooling, templates and recorded baseline metadata, not
downstream WordPress core, plugins, PHP deployments or databases. The signed
tooling ZIP excludes the optional runtime starter. Existing consumers do not
acquire the new plugin runtime merely by adopting this framework release.

Projects independently upgrading these plugins should use their normal
dependency-update review and the [baseline upgrade and rollback
procedure](../baseline-upgrades.md).

## Downstream Workflow Changes

The framework-managed GitHub validation, dependency-update, reconciliation, PR
blocker and framework self-update workflow templates change only the
`shivammathur/setup-php` commit pin from 2.37.2
(`f3e473d116dcccaddc5834248c87452386958240`) to 2.40.0
(`eb7c497e18156a6bbabfef1d3a82760b9eda3962`). The documented workflow examples
match. GitLab pipeline templates are unchanged. Customized downstream workflows
may be skipped by the framework installer and need the same pin update applied
manually.

## Required Downstream Actions

Adopt the signed release through the normal reviewed `framework-sync` process
and run downstream validation. Use
`framework-sync --check-only --fail-on-skipped-managed-files --json` when managed
workflow customizations must block adoption, and reconcile any skipped workflow
before merging. Separately qualify any intended runtime plugin update, including
form submission without real mail delivery; framework installation is not that
qualification.

## Operational Notes

The authoritative artifact remains `wp-core-base-vendor-snapshot.zip`, its
SHA-256 sidecar and detached signature. Both plugin archives were verified file
by file against the version-bound WordPress.org SHA-256 manifests before
adoption. Normal exact-revision validation, security review and publication
gates remain required. Both profiles are covered by real fresh-install and
seeded HPOS/legacy-order upgrade and paired rollback fixtures on PHP 8.3, 8.4
and 8.5. Those synthetic checks do not certify production data or external
payment, mail, Jetpack or form-provider integrations. The recorded WordPress
baseline security findings remain open; this release does not declare the
runtime security-cleared.
