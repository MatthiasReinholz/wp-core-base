# wp-core-base 1.6.4

## Summary

This patch release hardens update-PR metadata parsing and branch refresh authorization, closes diagnostic credential-redaction gaps, and fixes two support-coverage edge cases found in an independent follow-up audit.

## Downstream Impact

Upstream release-note content cannot replace the authoritative metadata appended by the updater. The reader selects the final metadata marker and rejects malformed final metadata without falling back to earlier content. Dependency, core and framework refreshes additionally require the selected branch to equal the PR's actual head before any branch mutation.

Early CLI parsing errors now use the same credential redaction as other errors. Diagnostic HTTP(S) URLs redact all user-information forms and sensitive query fields; download transport still requires HTTPS.

Malformed recognized forum entries leave support coverage incomplete while retaining earlier discoveries. Topic titles containing the empty-state wording no longer erase previously observed topics or support signals during refresh.

Branch cleanup now preserves a head used by any current same-repository open PR, including a reopened original PR. Incomplete inventory evidence prevents deletion; existing revision leases remain in place. Cleanup JSON adds a preservation reason and the reusing PR number without changing existing fields.

## Migration Notes

Existing manifests and normal update PRs require no migration. A PR whose recorded branch conflicts with its actual head now fails safely; review and repair its metadata or recreate it through the updater. The updater does not redirect a refresh to the conflicting branch.

## Downstream Workflow Changes

No framework-managed downstream workflow or pipeline template changes are required. Maintainer CI now retains structured test and observed-coverage reports for 14 days, and its pinned PHPStan analyzer is updated to 2.2.16. Those maintainer changes do not alter downstream permissions or runtime requirements.

## Required Downstream Actions

Adopt v1.6.4 through `framework-sync` or the signed framework snapshot, then run normal downstream validation. This release includes security hardening for automation metadata and diagnostic output. Review any existing PR with conflicting or malformed metadata before retrying it.

## Operational Notes

Official WordPress and plugin runtime files remain unchanged. The signed artifact contains framework tooling and documentation, and does not resolve the inherited runtime findings in the [baseline review](../security-reviews/2026-09-25-baseline.md).

The authoritative release assets remain `wp-core-base-vendor-snapshot.zip`, its checksum and detached signature. Publication requires successful CI and the exact-revision security review.
