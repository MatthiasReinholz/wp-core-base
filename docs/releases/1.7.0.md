# wp-core-base 1.7.0

## Summary

Release dependencies can require Sigstore verification through a generic manifest
policy. GitHub and GitLab release downloads verify the original package before
extraction against an exact certificate identity, OIDC issuer and bundle asset.
Missing or ambiguous bundles, altered packages and signer mismatches fail closed.

## Downstream Impact

Existing manifests retain their current behavior. An optional `source_config.sigstore`
object enables required signature verification independently of checksum-sidecar
policy. Publisher identities stay in downstream manifests; the framework contains
no publisher-specific rules. Re-adding or previewing an installed dependency
retains its existing signature policy unless explicitly replaced in reviewed config.

## Migration Notes

Use the signed framework snapshot and ordinary framework-sync preflight. For a
GitHub or GitLab release dependency, declare all three Sigstore policy fields:
`bundle_asset_pattern`, `certificate_identity` and `oidc_issuer`. The bundle must
verify the selected original package; it is not a checksum-sidecar substitute.
Review intentional signer changes in the downstream manifest.

## Downstream Workflow Changes

Generated GitHub validation, dependency-update and reconciliation workflows, and
the GitLab setup, now run `install-verification-tools` and add
`.wp-core-base/build/verification-tools` to `PATH`. The installer is a network-free
no-op when no managed dependency requires Sigstore. When required, it installs
Cosign 3.1.3 after checking its committed platform-specific SHA-256 digest.
Customized downstream workflows may be skipped by the framework installer and
must receive the same setup before any signed-dependency download.
Validation setup remains renderable by older installed framework clients and
preserves custom tool installation paths.

## Required Downstream Actions

1. Review `framework-sync --check-only --json`, adopt the signed snapshot and
   reconcile any skipped customized workflows before merging.
2. If enabling Sigstore, independently inspect the publisher's real bundle and
   commit the exact signer, issuer and bundle asset policy in the application.
3. Run `install-verification-tools` and export its build directory on `PATH` for
   local dependency operations; CI templates do this automatically. Unsupported
   automatic-install platforms need a trusted Cosign executable on `PATH`.
4. Run doctor, staging and the actual signed-release preview in protected CI.
   Cosign's initial trust-root setup may require HTTPS access; bundle verification
   uses offline transparency evidence. Missing tools or verification failures
   reject the package and must not be bypassed.

## Bundled Baseline

- WordPress core: `7.1.3`
- WooCommerce `11.2.1`
- Jetpack `16.3`
- Contact Form 7 `6.2.1`
- Redirection `5.10.1`

Framework adoption changes tooling, templates and metadata. It does not replace
the downstream WordPress core, plugin runtime or database baseline.
