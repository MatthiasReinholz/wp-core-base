# wp-core-base 1.6.0

## Summary

This release updates the optional starter baseline to WordPress 7.1.2, WooCommerce 11.1.2 and Jetpack 16.2 together. WooCommerce and Jetpack require WordPress 7.0 or newer. Existing-store upgrade tests now complement fresh-install runtime validation, including WooCommerce database migrations and paired database/runtime rollback.

Fresh-install and upgrade validation now fail on WordPress database errors as well as PHP fatal errors. The upgrade fixture verifies downloadable-product permissions and maximum-length table names through a complete snapshot and restore.

Managed release archives with an explicit subdirectory inside a wrapper folder are accepted correctly. Missing candidate paths no longer prevent discovery of the valid payload; symlink and archive-entry protections remain enforced.

## Downstream Impact

The signed framework snapshot updates tooling and documentation. Its baseline metadata does not replace a downstream repository's WordPress core, plugins, themes or manifest ownership decisions.

New projects using the tagged starter receive the updated baseline. Existing projects adopting these runtime versions must coordinate WordPress, WooCommerce and Jetpack updates and validate their own integrations.

## Migration Notes

WooCommerce 11.1 introduces database migrations and changes variation-gallery behavior. A Git rollback alone cannot undo database changes. Preserve a consistent database backup with the matching runtime and uploads before migration, rehearse restoration, and prevent new writes during any rollback window.

See [baseline upgrades](../baseline-upgrades.md) for the disposable seeded-store regression and downstream rollout procedure. Framework fixture coverage does not replace testing a restored store's themes, payment gateways, external services and custom extensions.

## Downstream Workflow Changes

No framework-managed downstream workflow or pipeline template changes are required. Upstream CI now runs seeded baseline upgrades and rollback checks for both repository profiles and WooCommerce's HPOS and legacy order storage, alongside the existing fresh-install smoke checks.

## Required Downstream Actions

For tooling-only adoption, run normal signed `framework-sync` preflight and review the resulting PR. Customized managed files can be checked with `framework-sync --check-only --fail-on-skipped-managed-files`.

For runtime adoption, deploy WordPress 7.0 or newer before activating WooCommerce 11.1.2 or Jetpack 16.2. Prefer the jointly tested 7.1.2 baseline, complete WordPress and WooCommerce database updates, and verify checkout, orders, administrative operations and integrations before reopening writes.

Akismet and the bundled themes retain their local ownership. Core ingestion does not replace those independently owned packages.

## Operational Notes

The signed `wp-core-base-vendor-snapshot.zip` remains a tooling-only distribution with the established asset name and layout. The normal prepare, review, merge and finalization workflows produce the release from a validated immutable commit.

The accompanying [security review](../security-reviews/2026-09-25-baseline.md) distinguishes specific scanner false positives from open upstream runtime findings. Those findings are not fixed by this framework release. Its migration checks establish the documented synthetic-store behavior; they do not provide blanket security clearance for WordPress or downstream sites.
