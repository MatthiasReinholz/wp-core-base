# wp-core-base 1.6.2

## Summary

This patch release closes local audit findings in credential redaction, bounded HTTP retries, release review enforcement and update-branch cleanup monitoring. Official WordPress and plugin runtime files are unchanged.

Sensitive query values are now redacted even when parameter names are encoded, repeated, dotted or bracketed. Common signed-download credential fields are also covered. Every HTTP retry delay, including fallback and exception paths, stays within the existing 15-minute per-delay cap, with overflow-safe conversion.

## Downstream Impact

Downstream repositories can adopt these framework fixes through `framework-sync` or the signed vendored snapshot. No manifest schema or CLI contract changes are required. Branch cleanup retains its existing ownership checks and exact-head lease; the identity checks are shared with read-only monitoring.

## Migration Notes

No special migration is required. Review the framework update and run the usual downstream validation before deployment. The framework ZIP contains tooling and documentation, not WordPress runtime files.

## Downstream Workflow Changes

No framework-managed downstream workflow or GitLab pipeline template changes are included. The new scanner publication gate and daily cleanup-residue report apply to the wp-core-base source repository's maintainer workflows only.

## Required Downstream Actions

Adopt the framework update to receive the redaction and retry fixes. Keep credentials in environment variables and review deployment-specific browser-content risks separately. This release does not clear the inherited WordPress findings documented in the [baseline review](../security-reviews/2026-09-25-baseline.md).

## Operational Notes

Both source-repository publication workflows now require a successful, fresh scanner review for the exact release commit before building or signing. A committed review register binds the existing open findings to their locations and affected source/minified file hashes. New, changed, missing or unverified findings block publication for review. Successful review explicitly reports `runtime_security_cleared: false`; scanner findings remain open and no upstream change is assumed.

The daily health report also checks recently closed managed update PRs for retained branches, with a 30-day lookback and one-hour grace by default. Changed branch heads require manual review, and branches reused by current same-repository open PRs are preserved. The monitor performs no deletion and fails if its bounded inventory is incomplete.

The authoritative asset remains `wp-core-base-vendor-snapshot.zip`, accompanied by its checksum and detached signature. Normal publication uses the merged release PR, required CI and exact-revision security review; published assets remain immutable.
