# wp-core-base 1.4.4

## Summary

- Added lifecycle cleanup for updater-managed pull-request branches after a
  dependency or framework-update pull request closes.
- Cleanup is deliberately constrained to same-repository branches whose pull
  request metadata, managed label, branch prefix, head SHA, and current remote
  SHA all agree. Deletion uses an atomic force-with-lease push.
- Added the `managed-pr-cleanup --pr-number=<number>` command for explicit,
  auditable cleanup and wired the same behavior into updater close paths.
- Kept framework synchronization merge-only: closing an unmerged framework
  update never applies framework files.
- Stabilized the multi-host integration contract fixture so each host layout is
  tested independently.

## Downstream Impact

- Framework-managed GitHub reconciliation workflows gain a separate cleanup job
  for closed updater-managed pull requests. The existing reconciliation job
  continues to run only for merged pull requests.
- GitHub cleanup requires job-scoped `contents: write` and
  `pull-requests: read`; no approval or merge permission is introduced.
- Updater close paths now remove their managed source branch only after the pull
  request has closed successfully and all ownership checks pass.
- Existing unmanaged branches, forks, default/base branches, unexpected branch
  names, mismatched SHAs, and ambiguously labelled pull requests are left intact.

## Migration Notes

- No application or content migration is required.
- Repositories using an unmodified framework-managed reconciliation workflow
  receive the cleanup job through normal framework synchronization.
- Repositories with a locally customized reconciliation workflow must reconcile
  that file manually; framework synchronization intentionally does not overwrite
  customized managed files.

## Downstream Workflow Changes

- `.github/workflows/wporg-updates-reconcile.yml` adds a cleanup job that runs on
  every labelled `pull_request_target: closed` event and checks out the trusted
  default branch before invoking `managed-pr-cleanup`.
- The reconciliation job remains guarded by `pull_request.merged == true` and
  retains its existing behavior.
- The cleanup job uses only `contents: write` and `pull-requests: read`. It does
  not autonomously review, approve, or merge dependency pull requests.

## Required Downstream Actions

1. Adopt the published `v1.4.4` vendor snapshot through the normal framework
   self-update pull request and review it before merge.
2. If `.github/workflows/wporg-updates-reconcile.yml` is customized, preserve
   local runner, secret, timeout, and bootstrap choices while adding the upstream
   cleanup job manually.
3. Run `framework-sync --check-only --fail-on-skipped-managed-files` and review
   every reported skip; a customized workflow skip is expected until reconciled.
4. Keep branch protection and the existing human or bot review policy in place.
   This release cleans up closed managed branches; it does not change who may
   approve or merge pull requests.
