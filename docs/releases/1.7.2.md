# wp-core-base 1.7.2

## Summary

This tooling patch publishes the bounded verifier-download fix from
[PR #136](https://github.com/MatthiasReinholz/wp-core-base/pull/136).
The optional pinned Cosign installer allows a 180-second executable transfer,
so large verifier artifacts are not constrained by the shorter metadata
deadline. Its ten-second connection limit, 256 MiB byte ceiling, allowed
download hosts, SHA-256 verification and atomic installation remain unchanged.

## Downstream Impact

Projects that configure Sigstore verification for hosted-release dependencies
receive the longer bounded transfer allowance when installing the pinned
verifier. An unsuccessful transfer remains an installation failure; the
installer does not fall back to an unverified executable or dependency.
When no managed dependency requires signatures, tool installation remains a
network-free no-op.

Verifier versions and digests, publisher identities, metadata timeouts and
dependency-download policies do not change. Framework sync updates tooling;
it does not upgrade downstream WordPress core, plugins, deployments or databases.

## Migration Notes

No manifest, credential or runtime-data migration is required. The installer
accepts the existing `JsonHttpTransport` contract, allowing the transfer policy
to be tested independently without downloading or executing the verifier.

## Downstream Workflow Changes

No framework-managed workflow or pipeline template changes are introduced
relative to v1.7.1. Required permissions and secret names are unchanged.

## Required Downstream Actions

Adopt the signed release through the normal reviewed `framework-sync` flow.
Preflight with `framework-sync --check-only --fail-on-skipped-managed-files --json`,
review any skipped or customized managed files, and run downstream validation
before merging the update. Consumers updating from older releases must also
review the intervening release notes.

Where signature verification is configured, run the normal
`install-verification-tools` step before dependency downloads. No publisher
trust configuration or permission increase is needed for this timeout fix.

## Operational Notes

The authoritative tooling artifact remains `wp-core-base-vendor-snapshot.zip`,
its SHA-256 sidecar and detached signature. The baseline section above tracks
the current source-tree starter. Previously published v1.7.2 artifacts remain
immutable; adopting the tooling artifact does not install or update the starter
runtime.

Regression coverage checks the bounded executable-transfer timeout, unchanged
byte ceiling and host allowlist, visible transfer failures, and the unconfigured
network-free path. The transfer-policy fixture stops before downloading an
executable; it does not claim a live upstream download or runtime migration.

Normal exact-revision CI, security review and verified publication gates remain
required. Previously published artifacts stay immutable, and the recorded
WordPress baseline findings remain open; this tooling release does not declare
the runtime security-cleared.
