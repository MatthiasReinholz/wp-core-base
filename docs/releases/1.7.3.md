# wp-core-base 1.7.3

## Summary

This patch release delivers the core and framework PR refresh fixes from
[PR143](https://github.com/MatthiasReinholz/wp-core-base/pull/143). Reapplying an
identical verified target archive no longer closes an update PR whose target is
still ahead of the current default base. Targets already present on base still
close through the existing exact-head cleanup path.

## Downstream Impact

Projects pinned to earlier framework releases receive the fix only after adopting
this signed tooling snapshot. Merging upstream source alone does not update their
vendored CLI. Plugin refresh behavior is unchanged because its refresh starts
from the default base.

The optional checksum transport parameter preserves the existing default HTTP
client, official core checksum endpoint and redirect policy. Framework signature,
checksum, payload identity and branch ownership checks remain required.

## Migration Notes

No manifest schema or configuration change is required. Existing update branches
and review work can be retained. An unchanged refresh preserves its exact remote
head and does not create an empty commit or a fictitious push receipt.

## Downstream Workflow Changes

No downstream workflow or pipeline template, permission, credential binding,
schedule, or runner requirement changes in this patch. The changed behavior is in
the core and framework refresh callers. Existing customized managed files retain
their normal review and strict preflight rules.

## Required Downstream Actions

Use the normal signed `framework-sync` update process. Review the generated PR,
run the project's native checks and merge it before considering the fix adopted.
Use `framework-sync --check-only --fail-on-skipped-managed-files` to identify
customized managed files that need review. No application image rollout is needed
solely to update repository-side automation tooling.

## Bundled Baseline

- WordPress core: `7.1.3`
- WooCommerce `11.3.0`
- Jetpack `16.3.1`
- Contact Form 7 `6.2.4.1`
- Redirection `5.10.1`

The baseline above describes the optional current source-tree starter. The signed
framework ZIP contains tooling and metadata; it does not install these core or
plugin versions into downstream projects. Their runtime manifests remain
separate. The WordPress 7.1.4 proposal is not included in this release, and the
reviewed open scanner and manual findings remain open; this patch does not claim
runtime security clearance.

## Operational Notes

The authoritative asset remains `wp-core-base-vendor-snapshot.zip`, accompanied
by its checksum and detached signature. This release is prepared with the normal
`prepare-framework-release` CLI and reviewed as `release/v1.7.3`. After its normal
CI and merge, `finalize-wp-core-base-release` must validate the exact merged main
commit before creating the annotated tag and publishing signed assets. Existing
published release bytes remain immutable.

Validation includes actual old-code failures and native Git regressions for
unchanged pending branches, genuinely satisfied base versions, normal changed
updates, and signed framework archive verification. It does not dismiss scanner
alerts or waive source review, release evidence, or downstream compatibility.
