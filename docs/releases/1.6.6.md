# wp-core-base 1.6.6

## Summary

This patch connects the production GitHub client to the shared label synchronizer.
Only a confirmed label GET `404` permits creation. Read, authorization and metadata
update failures remain visible instead of being masked by an attempted duplicate
creation. A structured `Label/name/already_exists` response is recovered once,
after verifying the existing label identity, while preserving canonical name,
color and description updates.

The release also records the independently reviewed WordPress 7.1.3, Jetpack 16.3
and WooCommerce 11.2.0 source-baseline updates merged since v1.6.5, and the
clarified downstream runtime-fixture migration guidance. Published older tags
and signed assets remain immutable.

## Downstream Impact

Concurrent label creation no longer aborts a sync when the requested label can be
verified and updated. Unrelated, mixed or malformed API errors still fail; an
existing permission or transport problem is not hidden. Actual-client HTTPS
regressions cover the production transport and bounded recovery.

The signed tooling snapshot does not install WordPress core, plugins or database
migrations into a downstream site. Source baseline metadata remains separate
from that site's runtime ownership and deployment.

## Migration Notes

No new manifest, workflow or database migration is required for the label fix.
Follow the [framework upgrade guide](../migration-guide.md#upgrading-an-existing-framework-installation)
when crossing earlier tooling-only release boundaries or maintaining customized
runtime fixtures. Preserve locally owned files and resolve skipped managed files
through the normal reviewed adoption process.

## Downstream Workflow Changes

No framework-managed downstream workflow or pipeline template changes are
included. Existing review, permission, smoke and release gates remain required.

## Required Downstream Actions

Adopt the signed release through `framework-sync`, review the resulting diff,
and run normal downstream validation. Use
`framework-sync --check-only --fail-on-skipped-managed-files --json` when customized
managed files must block rollout. Run `doctor --automation` and `stage-runtime`
for the downstream profile, then rerun the failed updater reconciliation.
Do not close a source-failure incident until that actual consumer run succeeds.

## Bundled Baseline

- WordPress core: `7.1.3`
- WooCommerce `11.2.1`
- Jetpack `16.3`
- Contact Form 7 `6.1.7`
- Redirection `5.10.1`

The optional source baseline preserves official upstream runtime code. Separate
adoption of WooCommerce 11.2.0 requires a verified database backup, completion of
its migration callbacks and checkout acceptance. Runtime rollback alone does not
reverse database changes; use the paired database/runtime restoration procedure.
Framework sync itself does not perform that plugin upgrade.

## Operational Notes

The authoritative artifact remains `wp-core-base-vendor-snapshot.zip`, its
SHA-256 checksum sidecar and detached signature. Normal exact-revision CI and
security review must pass before publication. The documented baseline security
findings remain open; successful framework publication is not runtime security
clearance. The separate Contact Form 7 baseline/ruleset decision is unchanged.
